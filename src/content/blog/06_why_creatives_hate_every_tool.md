# Why Creatives Hate Every Time Tracking Tool Ever Made (And What Would Have to Change)

*The problem isn't that agencies haven't tried enough tools. The problem is that every tool in the market shares the same set of broken assumptions.*

---

Search G2 or Capterra for "time tracking for agencies" and you'll find dozens of options. Harvest, Toggl, Clockify, Streamtime, Productive, Scoro, Workamajig, Function Point, Kantata, Timely, Clockk, Replicon, Allfred. Each has its strengths. Each has thousands of users. Each has glowing reviews from project managers and finance leads.

Now search for reviews from the people who actually have to use them, the creatives, and a different picture emerges.

"Difficult to navigate." "Overly complex and convoluted." "To-do board times out." "Bulky and not really intuitive." "Measuring time seems to be the last thing this product was set up for."

These aren't reviews of bad products. They're reviews of products designed for the wrong person.

## The five assumptions every tool shares

Walk through the interaction model of any time tracking tool on the market, and you'll find the same core assumptions embedded in every one:

**Assumption 1: The person who does the work records the time.**

Every tool, without exception, is built around the individual user experience. One person, one timer, one timesheet. But at agencies with 150-350 people, senior creatives almost never file their own timesheets. EAs and creative coordinators do it for them. This proxy workflow is the dominant pattern at large agencies, and no tool provides a first-class interface for it.

**Assumption 2: The primary interface is a web application.**

You open the app. You navigate to the right project. You start a timer or enter hours manually. You add notes. You submit.

But creatives live in Slack, Figma, Google Docs, and Photoshop. Asking them to context-switch into a separate time tracking application, find it, log in, navigate, enter data, is asking them to leave their actual workspace to visit a compliance tool. As Gloria Mark's research shows, each context switch costs 23 minutes of recovery. The tool itself becomes the interruption.

**Assumption 3: Time entry means forms and grids.**

Hours and minutes in rows and columns. Fifteen-minute increments. Select project from dropdown. Select task from sub-dropdown. Enter start time, end time, or duration. Add notes. Repeat.

This is a data entry interface. It was designed to capture structured information in a format that's easy for accounting software to process. It was not designed for a human brain trying to reconstruct a fragmented, nonlinear work day.

**Assumption 4: Tracking requires active participation.**

Start the timer. Stop the timer. Remember to start the timer. Remember to stop the timer. Forgot to start the timer? Enter time manually later, from memory.

The entire paradigm places the cognitive burden on the worker. They must decide when to track, what to track, which project to assign it to, and how long it took. Every step is a decision point. For people already managing dozens of creative decisions per hour, adding administrative decisions to the stack is pure overhead.

**Assumption 5: Onboarding is acceptable.**

Create an account. Set a password. Download the app. Configure your projects. Learn the interface. Watch the tutorial. Attend the training session.

For creative professionals who already hate the concept of time tracking, every onboarding step is a conversion drop-off. By the time they've completed setup, they've already decided this is a tool they'll avoid whenever possible.

## The AI tools fixed one problem and kept the rest

A new generation of tools,Timely, Clockk, Rize, addressed Assumption 4 by introducing passive tracking. Background agents observe which apps and websites you use and draft time entries automatically.

This is genuine progress. But it comes with a critical constraint: every one of these tools requires a **desktop application to be installed**. An agent running on your machine, watching which windows are active.

For many creatives, this triggers exactly the surveillance anxiety that made them hate time tracking in the first place. One creative technologist at a major agency was shown a demo of passive tracking and responded categorically: "Even if it worked perfectly, I wouldn't install it."

And even when creatives accept the agent, the output is still presented as a traditional timesheet, rows of entries in a grid. The capture method changed. The interface didn't. The proxy workflow still isn't supported. The channel-first delivery doesn't exist.

## What the reviews actually say

Reading through agency-user reviews on G2, Capterra, and industry forums surfaces consistent themes:

**On Scoro:** "Overly complex and convoluted." "Four to eight week learning curve." Weak mobile. "Measuring time seems to be the last thing this product was set up for."

**On Workamajig:** "Reporting limitations." "Data sync errors." "To-do board times out." "Steep admin learning curve." Thirty years in market, but the UX hasn't kept pace.

**On Function Point:** "Difficult to navigate." "Features not obvious, need a dedicated SME." Time tracking described as "restrictive and difficult to customize."

**On Kantata:** "Task management restrictive." "Excessive clicking." Fifty-seat minimum.

**On Harvest** (post-Bending Spoons acquisition): "Bulky and not really intuitive." Pricing restructured, some agencies report 6x price increases. Safari issues. Mobile gaps.

The pattern across all of them: the product works well enough for the person managing the system (the PM, the finance lead, the ops director) but creates friction for the person forced to use it (the creative).

This is not a coincidence. These tools were designed for administrators. Creatives are just the data input mechanism.

## What would have to be different

If you started from scratch, if you threw away every assumption and designed a time tracking experience specifically for creative professionals at agencies, what would it look like?

**No app to install.** A notification arrives through a channel they already use: Slack, WhatsApp, SMS. A magic link opens a single-page web view. No account creation, no password, no onboarding.

**No blank form.** The system has already drafted their week from calendar data, project tool activity, and meeting attendance. The creative sees a pre-populated view of their time allocation, not an empty grid.

**Not a grid.** A pie chart showing how their week breaks down by project. Five colored segments. The proportions are immediately scannable. "Does this look right?" If not, drag a segment to adjust. Five percent snap increments, not fifteen-minute blocks.

**No timer.** No "start" and "stop" buttons. No need to remember to track in real time. The system observes passively through integrations, not through an installed agent.

**A proxy-manager workflow.** For the EA who files for twelve people, a group view showing everyone's draft, with batch review and submission. Not twelve separate sessions in twelve separate tabs.

**Thirty seconds, not thirty minutes.** The entire interaction, receive notification, open link, glance at pie chart, adjust one segment, confirm, takes less than a minute. The creative's week is recorded. The data is accurate. And they never opened a time tracking application.

## The empty quadrant

Map every time tracking tool on two axes: friction (high to low) and delivery model (app-first to channel-first).

Every existing tool clusters in the high-friction, app-first quadrant. Some have reduced friction through automation (Timely, Clockk), but they're still app-first. Some have added Slack integrations (Harvest, Toggl), but the Slack bot is a secondary input, not the primary experience.

The low-friction, channel-first quadrant is empty. No tool treats the messaging channel as the primary surface. No tool delivers a pre-filled, visual, confirmation-based timesheet through the channels creatives already live in.

That's not a feature gap. That's an entirely different product philosophy. And it's the reason every tool in the market, despite years of iteration and millions in investment, still produces the same reaction from creatives: they hate it.

The question isn't "which tool should we use?" The question is: "what if the tool met creatives where they already are, with the work already done?"
